## Implemented workflows

### Non-striker run out before delivery

- Available through cricket **Options → Non-striker run out before delivery**
  and the current non-striker's player menu.
- The confirmation explicitly records the umpire's Out decision when the ball
  was not delivered. It adds one wicket and records the bowler as fielder,
  without bowler wicket credit. Runs/extras, legal balls, balls faced, bowler
  workload, strike and a pending free hit remain unchanged.
- The existing reversible checkpoint mechanism stores a typed non-delivery
  event and the exact pre-action state. No fake dot-ball/wicket delivery is
  added. Fall of wickets and a distinct history section explain what happened.
- The incoming batter occupies the non-striker's end. All-out closes the innings
  without an unnecessary selection prompt or extra ball.
- Undo reverses a following delivery first, then this action. Earlier balls
  stay protected by the checkpoint; later-innings progression prevents an unsafe
  earlier checkpoint reversal. Scorecard corrections remain available.
- Save/reload retains the event, checkpoint and pending selections. Confirmation
  tokens reject changes to actors, innings, scores, conditions or finalisation.

### Abandoned/no-result and reopening

- **Options → End match / record outcome** offers the available score-based
  result, an explicit end without a recorded result, abandonment, or an official
  no-result decision. The note is optional and limited to 500 characters.
- The always-scrollable explanation states that scoring stops, history stays saved,
  and no competition minimum-overs, tie-break or DLS decision is inferred.
- Ending play does not turn an unfinished innings into a natural completion or
  invent a winning run margin. Explicit outcomes survive scorecard correction,
  correction reversal, renaming and JSON recovery.
- **Options → Review outcome / reopen match** shows the saved outcome/note.
  Reopening clears it, retains corrected figures, restores the previous break
  and selection state, and reevaluates any naturally completed innings.
- Pre-toss abandonment is supported. The toss, roles, strike and innings commands
  cannot change a finalised match until it is reopened; scorecard/team correction
  follows its existing explicit workflow.
- The main recovery path now retains finalised cricket matches until explicit
  reset, including an abandonment before any delivery. This fixes the previous
  deletion on finalisation. The saved-match prompt identifies the recorded outcome.
- Compact output shows **ABANDONED / NO RESULT** instead of rotating live chase
  context. A finalised pre-toss match displays this state instead of the toss screen.
  A pending free hit is retained in state for reopening but hidden while ended.

### Related lifecycle fix

The integration test exposed a native adapter failure when closing a window
before its first Show: the Closed handler read `Screens` after/until backend
initialisation was unavailable. `NativeWindow` now unsubscribes only the screen
object it actually observed. Owned and unowned close-before-Show cases are covered.

| Clause | Applied meaning |
| --- | --- |
| 38.3.1–38.3.2 | Umpire-decided non-striker run-out when the ball is not delivered; no ball counts in the over. The app records the decision rather than judging ground/timing/appeal conditions. |
| 38.6 | Run-outs do not give the bowler wicket credit. |
| 3.1–3.3 | Scorers record wickets/runs/overs and accept umpire instructions/signals; the operator supplies the decision. |
| 13.1.2 and 16.4 | Agreed playing conditions determine result criteria when an ordinary win does not apply. No minimum-over or DLS threshold was guessed. |
| 16.1–16.2, 16.5 | Ordinary win/tie/draw criteria do not justify inventing a run margin simply by ending an unfinished chase. |

The delivered event is specifically **not delivered**. Law 38.3.3's case where the
ball is subsequently delivered, penalty/disallowed-run combinations, and physical
appeal/timing adjudication are not represented as automatically handled.

## Remaining product decisions and backlog

1. Select supported competitions and adopted law editions before automatic
   minimum-overs, result qualification, tie-breaks, declaration/forfeiture,
   retirement-return consent or replacement eligibility rules are added.
2. Keep delivered-but-disregarded run-out events (38.3.3), penalty runs, short/
   disallowed runs and catch-preventing obstruction as distinct future event types.
3. Extend audited result dispositions to awarded/conceded matches and time-expiry
   draws if required. Current abandonment/no-result choices are explicit operator
   records, not a competition rules calculator. No DLS implementation was added.
4. Retain the earlier cross-innings correction boundaries. Legacy finalised saves
   without a reopening checkpoint cannot be safely reopened by guessing; the UI
   explains that their figures remain reviewable/correctable.
5. Native Mac focus, Retina/multiple-display, popup edge/fullscreen and long-running
   AFL freeze checks remain required. This executor is Linux; no Mac CI was run
   for these local batches.
