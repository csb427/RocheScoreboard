## Chart semantics and limits

Each team innings is a separate series on the same legal-over axis; **totals are
not merged across innings**. Match innings number and team innings ordinal remain
separate, so a follow-on does not become an incorrectly labelled team innings.
Unplayed innings are not invented. Unequal lengths and a single played innings
remain valid series. Legends use abbreviations and truncate long names within
their own area.

Extras before a legal ball remain at the same x position. A before-delivery
run-out adds a wicket marker without inventing a ball. Scorecard corrections
are explicitly marked as incomplete/adjusted history: the worm breaks across
the correction and marks the corrected endpoint; Manhattan continues to show
recorded runs per over rather than allocating unrecorded runs to invented overs.
No scoring laws, competition result criteria or DLS calculations changed.

The supported competition workflow currently has two or four innings. Tests
cover those identities, follow-on ordering, partial/unequal overs and pages.
Malformed historical records whose team identity is already ambiguous are not
claimed to be repaired by a chart renderer.

## Integration and motion decisions

Original WPF source/controllers and shared models remain authoritative; Avalonia
files were regenerated. A new `OperatorChoiceSurface` draws through the existing
`OperatorLiquidSelection` geometry/material code, driven by the existing
`OperatorChoiceMotion` property and animation clock. There is no second animation
system or third-party runtime. Shared material arrival is 500 ms; selection fill
is 440 ms; command execution is immediate. General/player menu exits remain
shorter. Public output windows retain broadcast presentation behavior rather
than the operator window's arrival treatment.

Selective skills used: Roche development guidance, design-motion-principles,
fluid-design and .NET assertion/test-gap guidance, plus the available Impeccable
craft guidance. The Liquid Glass skill was inspected for applicability; this
WPF/Avalonia code does not call SwiftUI/AppKit glass APIs. No omitted skill script,
installer, hook, credentials or external-agent access was used.

The new menu template exposed a translator defect: template-local transforms
were being emitted as controller fields, creating duplicate `TbSc` declarations.
The translator now records template scope before removing object names and
excludes those objects from controller fields. The fixture with both templates
now compiles and exercises their independent runtime behavior.
